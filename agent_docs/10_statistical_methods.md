## Мотивация

Классический консенсус TAD-детекторов (deepTAD-style) использует мажоритарное
голосование: граница включается если её детектировали ≥ k алгоритмов из N.
Это равновесная схема: все алгоритмы имеют одинаковый вес независимо от их
биологической точности.

**Центральный тезис диплома:**
Равновесный консенсус биологически неинформативен, потому что:
1. Алгоритмы с низким center_ratio (scktld~1.02, topdom~0.80) разбавляют сигнал
2. Алгоритм с высоким FPR (armatus: 422 границы на chr1) вносит шум пропорционально
3. Нет механизма учёта разреженности Hi-C карты (пустые регионы = ложные границы)

Все три статистических метода адресуют разные аспекты этой проблемы.

## Метод 3: Взвешенный консенсус по ChIP-seq center_ratio

### Теория

**Постановка.** Пусть имеется N алгоритмов и множество кандидатных позиций
{b_j}. Для каждой позиции:

    B_j = Σ_i [w_i · 1(algo_i детектировал b_j ± tol)] / Σ_i w_i ≥ θ

где веса w_i ∝ center_ratio(algo_i) — биологическая точность алгоритма
по RAD21 ChIP-seq (chr1@100kb).

**Нелинейные трансформы весов** (M3v2):

```
linear:  w_i = max(0, cr_i)
         Проблема: armatus (cr=1.149) получает 73% веса ontad (cr=1.423)

power:   w_i = max(0, cr_i − baseline)^γ,  baseline=1.0, γ=2.0
         cr < baseline → w=0 автоматически (topdom cr=0.798 → 0)
         ontad:   (1.423−1)^2 = 0.179  →  59% Σw
         armatus: (1.149−1)^2 = 0.022  →   7% Σw  (−8× vs linear)
         scktld:  (1.020−1)^2 = 0.0004 →   0.1% Σw

softmax: w_i = exp(α·(cr_i − baseline)),  α=5
         Мягкое усиление; cr<baseline → w<1 (не 0)

zscore:  w_i = max(0, (cr_i − μ) / σ)
         Робастный: не требует гиперпараметров; обнуляет cr < mean
```

### Результаты

| Хром | Res | Transform | RAD21 ctr | n_bnd | Verdict |
|------|-----|-----------|-----------|-------|---------|
| chr1  | 100kb | linear  | 1.118 | 338 | STRONG |
| chr1  | 100kb | power   | 1.119 | 351 | STRONG |
| chr1  | 50kb  | power   | 1.278 | 227 | STRONG |
| chr18 | 25kb  | power   | 1.881 | 145 | **>Arrowhead** |
| chr21 | 25kb  | power   | 1.709 | 74  | **>Arrowhead** |
| chr20 | 25kb  | power   | 1.468 | 178 | ≈Arrowhead |

### Ключевой вывод

Power-трансформ корректно подавляет слабые алгоритмы, но center_ratio на 100kb
остаётся ~1.12 (vs strong_consensus 1.382). Причина: **архитектурный потолок
метода на уровне отдельных границ**. Все алгоритмы предсказывают границы в
одних и тех же позициях (они работают с одной матрицей). Перевешивание меняет
score каждой позиции, но не набор позиций выше порога. Strong_consensus
превосходит weighted потому что использует **TAD-уровневый геометрический
критерий** (обе границы воспроизведены), а не агрегирует одиночные границы.

**Вывод для диплома:** взвешивание по биологическому критерию улучшает консенсус
на высоком разрешении (25kb: cr=1.88, +29% vs Arrowhead), но на 100kb не
преодолевает ограничение позиционной неопределённости.

## Метод 4: Пермутационный тест ChIP-seq обогащения

### Теория

**Постановка.** Для каждой границы b_j вычисляется наблюдаемая плотность
ChIP-seq пиков:

    obs_density_j = #{peaks ∈ [b_j−w, b_j+w]} / (2w)

Нулевое распределение строится из N=1000 случайных позиций на той же
хромосоме (исключая теломерные регионы ±3Mb):

    null_density_k = #{peaks ∈ [r_k−w, r_k+w]} / (2w),  r_k ~ Uniform(telo, L−telo)

Эмпирический p-value (одностороннее правое):

    p_j = #{k : null_density_k ≥ obs_density_j} / N

FDR-коррекция: Benjamini-Hochberg без внешних зависимостей (собственная
реализация с монотонностью).

### Результаты и диагноз

| Хром | Res | Track | n_input | n_significant | Причина |
|------|-----|-------|---------|---------------|---------|
| chr1 | 100kb | RAD21 | 241 | 1 | Статистическая мощность = 0 |
| chr1 | 100kb | SMC3  | 241 | 1 | Аналогично |
| chr1 | 100kb | CTCF  | 241 | 0 | Аналогично |

**Корневая причина:**

```
RAD21 пиков на chr1:          2 256
Плотность:                    ~9 пиков/Mb
Окно ±50kb = 100kb:           ~0.9 пика ожидается случайно
Разрешение консенсусной границы: 100kb = ±50kb позиционная ошибка
```

При 100kb разрешении позиционная неопределённость границы сравнима с шириной
окна подсчёта. Граница chr1:0−100000 (центр=50kb) отражает весь теломерный
регион, где ChIP-seq сигнал нулевой. Большинство obs_count = 0−1, нулевое
распределение то же самое → тест честно сообщает об отсутствии различимости.

**Метод применим при:**
- Разрешение ≤ 25kb (позиционная точность ≥ 2× ширины окна)
- Плотные треки (CTCF: 44k пиков; RAD21: 2k — мало)
- window_bp ≥ resolution (покрывать несколько бинов)

**Два выживших пика (center_ratio=1.803/2.695)** — настоящие биологические
хотспоты с высочайшей концентрацией факторов. Метод правильно их находит.

## Метод 1: PELT change-point на Insulation Score (PoC)

### Теория

**Insulation Score** (Crane et al. 2015):

    IS[i] = mean(M[i−w : i,  i : i+w])

Минимумы IS соответствуют позициям с низким числом контактов между соседними
регионами — потенциальным границам TAD.

**PELT** (Pruned Exact Linear Time, Killick et al. 2012):
Оптимальное разбиение сигнала на сегменты с минимизацией:

    C(y_{1:T}) + β · |{change-points}|

где β — штраф за добавление breakpoint, C — стоимость (здесь: RBF kernel).

**Стабильность по β-сетке:** граница включается если детектирована при
≥ min_beta_support значениях β из сетки [β_min, β_max].
Это эквивалентно bootstrap по модели: устойчивые к изменению штрафа
breakpoints — более достоверные границы.

### Результаты

| Хром | Res | n_bnd | RAD21 ctr | Verdict |
|------|-----|-------|-----------|---------|
| chr17 | 25kb | 370 | 1.205 | STRONG |
| chr1  | 100kb | 208 | 0.958 | FLAT |

**Вывод:** IS-минимумы на 25kb совпадают с CTCF-якорями (STRONG).
На 100kb IS слишком груб: diamond-окно 5 bins = 500kb покрывает несколько TAD
одновременно, минимумы смещены на -145kb от истинных границ.

**Для диплома (PoC):** метод доказывает, что изоляционный сигнал Hi-C несёт
биологическую информацию на 25kb, но требует post-processing (смещение -145kb
нужно учитывать).

## Метод 5: Вероятностная модель границ (EM)

### Теория

**Постановка (latent variable model, Dawid-Skene 1979 style):**

Для каждой позиции-кандидата b:
```
z_b ∈ {0,1}       — латентная переменная: истинная граница?
x_{ib} ∈ {0,1}    — алгоритм i детектировал границу в b (±tol)
```

Генеративная модель:
```
P(x_{ib}=1 | z_b=1) = sens_i    ← чувствительность алгоритма i
P(x_{ib}=1 | z_b=0) = fpr_i     ← частота ложных срабатываний
P(z_b=1)            = π_b        ← приор (из локального Hi-C сигнала)
```

**Ключевое отличие от M3:** M3 учитывает только чувствительность (через
center_ratio). M5 явно моделирует FPR: алгоритм с 422 границами на chr1
(armatus) получает fpr ≈ 0.17, тогда как ontad (110 границ) → fpr ≈ 0.05.
Это означает, что согласие armatus с ontad существенно менее информативно,
чем согласие двух алгоритмов с низким FPR.

**Инициализация параметров:**

```
sens_i = sigmoid(k · max(0, cr_i − 1.0))
         cr=1.0 → sens=0.5 (нет информации)
         cr=1.42 → sens=0.97 (онтад)
         cr=1.02 → sens=0.58 (scktld — почти случайный)

fpr_i  = n_boundaries_i / n_bins  ∈ [fpr_min, fpr_max]
         armatus:       422/2492 = 0.169
         ontad:         110/2492 = 0.044
         scktld:        ~120/2492 = 0.048

π_b = sigmoid(k_prior · (local_signal_b/mean_signal − 1))
      local_signal_b = sum(M[b±1, b±1])  (3×3 diagonal neighbourhood)
      Пустые регионы: local_signal≈0 → π_b = sigmoid(−k_prior) ≈ 0.05
      Плотные регионы: π_b → 0.95
```

**EM-алгоритм:**

E-шаг (апостериорная вероятность):
```
log P(x_{·b} | z=1) = Σ_i [x_{ib}·log(sens_i) + (1−x_{ib})·log(1−sens_i)]
log P(x_{·b} | z=0) = Σ_i [x_{ib}·log(fpr_i)  + (1−x_{ib})·log(1−fpr_i)]

q_b = P(z_b=1 | x_{·b}) = sigmoid(log(π_b/(1−π_b)) + log_p1_b − log_p0_b)
```

M-шаг (обновление параметров):
```
sens_i^new = Σ_b q_b · x_{ib} / Σ_b q_b
fpr_i^new  = Σ_b (1−q_b) · x_{ib} / Σ_b (1−q_b)
```

Сходимость: |ΔLL| < tol = 1e-4, max_iter = 50.

**Выход:** граница включается если q_b ≥ θ = 0.5.

### Ожидаемое улучшение vs M3

На chr1@100kb:
- armatus имеет fpr=0.169 >> ontad fpr=0.044
- M3 power: ontad весит 59% Σw, armatus 7%
- M5: при согласии ontad+modularity_tad (оба fpr~0.04-0.09):
  log P(x|z=1) >> log P(x|z=0) → q_b → 1
  При согласии только armatus с тем же набором:
  fpr_armatus высокий → log P(x|z=0) тоже высокое → q_b значительно ниже

Итого: M5 должен превзойти M3 именно в случаях когда armatus/scktld
добавляют ложные границы, которые M3 не мог отклонить из-за отсутствия
механизма FPR.
